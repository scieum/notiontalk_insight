# insight-evaluator

> 상태: **구현 완료 — 실 LLM 호출만 미검증 (2026-08-26)**. 설계서 §2.3, §2.4 A5, §4.3.
>
> 4축 중 충실성·근거일치·공개적절성은 LLM 채점(스레드 단위 1회 호출),
> 중복은 스크립트가 임베딩 코사인 유사도로 계산한다. 가짜 LLM·가짜 임베딩으로
> 전 분기를 검증했다(통과 / 공개부적절→에스컬레이션 / 근거실패→재생성→재채점 /
> 재생성실패→폐기 / 유사도≥0.9→병합 / 채점실패→미채점).

## 스크립트

| 파일 | 역할 |
|------|------|
| `scripts/eval_prompt.py` | 평가 프롬프트 조립 (**A4의 `extract_prompt.py`와 완전히 별개 파일**) |
| `scripts/evaluate.py` | 채점 → 재생성 → 재채점 → 중복 판정 → `eval.json` |

```
.venv/bin/python .claude/agents/insight-evaluator/scripts/evaluate.py \
    --draft output/insights/period_<id>.draft.json
```

## 판정 결과 (`eval.json`의 `decision`)

| 값 | 뜻 | 다음 단계 |
|----|----|----------|
| `통과` | 4축 모두 통과 | A6(PII 마스킹)로 |
| `병합` | 기존 KB 항목과 유사도 ≥ 0.9 | 신규 발행 대신 기존 항목에 근거 추가 |
| `폐기` | 충실성·근거 실패 후 재생성까지 실패 | 발행하지 않음 |
| `에스컬레이션` | 공개 적절성 실패 | **자동 발행 금지**, 운영자 판단 |
| `미채점` | 채점 자체가 스키마 실패 | 통과로 위장하지 않는다. 발행하지 않음 |

## C9 준수 방법

- 평가 프롬프트 파일이 생성 프롬프트 파일과 분리돼 있다. import해 재사용하지 않는다 —
  재사용하면 평가자가 생성자의 지시문을 물려받아 같은 편향으로 채점한다.
- **재생성조차 평가자가 하지 않는다.** `_regenerate_thread()`는 insight-extractor의
  프롬프트로 별도 호출하고, 평가 사유는 A4의 '반려 사유' 자리로 주입한다.

## 알려진 한계

- **중복 축은 현재 항상 미실시**다. 비교 대상인 `kb.sqlite`의 chat 원천 청크를
  채우는 kb-builder(A8)가 아직 없다. 미실시는 `duplicate_checked: false`로
  기록되며 통과로 위장하지 않는다.

## 역할

생성(`insight-extractor`)과 완전히 분리된 호출로, draft.json의 각 항목을 4개 축으로 채점한다.

1. **원문 충실성**: 요약이 원문을 왜곡·과장하지 않았는가
2. **근거 일치**: `source_message_ids`가 실제로 해당 내용을 지지하는가
3. **중복**: 기존 FAQ/팁과 유사도(kb-search가 사전 계산해 제공) ≥ 0.9면 신규 발행 대신
   기존 항목에 "추가 근거"로 병합 판정
4. **공개 적절성**: 민감 발언·저격·개인 사정 포함 여부

## 입력

- draft.json 경로 (`insight-extractor` 출력)
- 원문 threads.json 경로
- kb-search가 사전 계산한 유사도 파일

## 출력

- `/output/insights/period_<id>.eval.json`

## 실패 처리 (CLAUDE.md §5)

| 실패 | 처리 |
|------|------|
| 충실성·근거 실패 | 해당 항목 재생성 1회 → 재실패 시 폐기+로그 |
| 공개 적절성 실패 | 에스컬레이션(운영자 판단, 자동 발행 금지) |
| 유사도 ≥ 0.9 | 신규 발행 대신 기존 항목에 병합 |
| 리포트 자체 실패 | 재생성 1회 → 에스컬레이션 |

## 참조 스킬

gemini-client, kb-search(유사도 계산은 스크립트가 사전 수행)
