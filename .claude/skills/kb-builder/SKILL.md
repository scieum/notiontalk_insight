# kb-builder (A8, B1, B2)

> 상태: **미구현 (V4 예정)**. 설계서 §2.4 A8, §2.5 B1/B2.

## 목적

지식베이스(kb.sqlite)를 채우는 유일한 스킬. 채팅 원천은 A8에서, 문서 원천은
B1(크롤링)→B2(청킹·임베딩)에서 갱신한다.

## B1 — 문서 크롤링 (주 1회)

- `/docs/sources.yaml` 시드 → 허용 도메인 내 링크 추적 → HTML 본문 추출 → md 변환
- 콘텐츠 해시 비교로 변경 페이지만 갱신
- 페이지 수 -20% 초과 감소 시 에스컬레이션(사이트 구조 변경 의심), 기존 KB 유지

## B2 — 청킹·임베딩

- 헤딩 기준 섹션 청킹(300~800 토큰, 오버랩 50), 청크마다 원문 URL·헤딩 경로·갱신일 메타
- 변경 페이지의 구청크는 `superseded` 표시(삭제 없음, C8)

## A8 — KB 갱신 (채팅 원천)

- FAQ·팁은 항목 단위 청크(질문+답변 결합), 스레드 원문은 스레드 단위 청크
- 신규 청크 수 = 항목 수 + 스레드 수(잡담 제외)

## 스크립트

| 스크립트 | 역할 | 상태 |
|---------|------|------|
| `scripts/crawl.py` | B1 문서 크롤링 | 미구현 |
| `scripts/chunk.py` | B2 원천별 청킹 규칙 | 미구현 |
| `scripts/embed.py` | 임베딩 후 kb.sqlite 저장 (A8/B2 공용) | 미구현 |
