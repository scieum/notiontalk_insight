# 카카오톡 내보내기 txt 형식 (kakao_txt_formats.md)

> 설계서 §6 O1'''. **미검증.** 아래는 웹 조사로 확인한 두 가지 알려진 형식이다.
> Mac 오픈채팅방 "대화 내보내기"로 실제 생성한 파일로 아직 대조하지 못했다.
> `parse_txt.py`는 이 두 형식을 모두 시도하도록 짜여 있으니, 실제 Mac 파일을
> 확보하면 이 문서와 파서의 정규식을 함께 갱신한다.

## 형식 A — 쉼표 구분 (최근 모바일 내보내기에서 확인, 확인일 2026-08-26)

```
2023. 6. 2. 오후 11:46, 홍길동 : 안녕하세요
2023. 6. 2. 오후 11:47, 김철수 : 네 안녕하세요 https://example.com
```

- 날짜: `YYYY. M. D.` (앞자리 0 없음 가능)
- 시각: `오전|오후 H:MM`
- 구분자: 날짜/시각과 닉네임 사이 쉼표, 닉네임과 본문 사이 콜론
- 출처: gpters.org 블로그 글 (모바일 내보내기로 명시), Citizen Data Scientist 블로그(전처리 글, "일시, 유저이름 : 작성 내용")

## 형식 B — 대괄호 구분 + 별도 날짜 헤더 (설계서 §1.4 원 저자 가정, 출처 불명)

```
--------------- 2023년 6월 2일 금요일 ---------------
[홍길동] [오후 11:46] 안녕하세요
[김철수] [오후 11:47] 네 안녕하세요
```

- 날짜 헤더 라인이 메시지 라인과 분리되어 있고, 이후 메시지 라인은 시각만 표기
- 설계서 §1.4 입력 정의 표에 이 형식으로 서술되어 있으나, 이번 조사에서 1차 출처를
  다시 확인하지는 못했다 — 예전 PC판 형식일 가능성

## 시스템 메시지 (입장/퇴장 등)

- `OOO님이 들어왔습니다.` / `OOO님이 나갔습니다.` 형태로 알려짐 (초대·사진·이모티콘 등도 유사)
- 시각 브래킷/쉼표 없이 단독 라인으로 나오는 경우와, 메시지 라인 형식 안에 포함되는
  경우가 둘 다 보고됨 — 확실하지 않음

## Mac 관련 특이사항

- 이번 조사에서 Mac 오픈채팅방 내보내기의 실제 원문 샘플을 확보하지 못했다.
- 오픈채팅방은 1:1/일반 그룹과 달리 "대화 내보내기" 메뉴 자체가 없을 가능성도
  있다(§6 O1''' "오픈채팅방 내보내기 지원 여부" 미해결) — 이게 확인되지 않으면
  A0'(폴백)이 애초에 성립하지 않을 수 있으므로 **V1' 착수 시 가장 먼저 확인**.

## 형식 B 실기기 샘플 확인 결과 (2026-08-31, "노션하는 교사톡" 방 txt 내보내기 실물)

`parse_csv.py`(운영 경로)와 별개로, 형식 B(대괄호 + 별도 날짜 헤더) txt 실물을 처음
확보해 대조했다. 형식 A는 이 방에서는 관측되지 않음(다른 내보내기 UI/버전 차이로 추정).

- 첫 줄은 `<방이름> 님과 카카오톡 대화` — 방 이름이 가변이라 접두사가 아니라
  접미사(`님과 카카오톡 대화`로 끝남)로 헤더 판정해야 한다. 기존 `SKIP_LINE_RE`는
  접두사만 봐서 이 줄을 놓쳤다.
- **멀티라인 메시지**가 흔하다 — 사용자가 줄바꿈을 포함해 보낸 메시지는
  `[닉네임] [시각] 첫줄` 다음에 접두사 없는 후속 줄(들)이 그대로 이어진다.
  기존 파서는 후속 줄을 전부 "미파싱 라인"으로 세서, 이 방 실데이터(416줄)에서
  파싱률이 80.5%까지 떨어졌다. 후속 줄은 직전 메시지 본문에 개행으로 이어붙이도록
  고쳤다(직전 메시지가 있을 때만 — 파일 맨 앞처럼 직전 메시지가 없으면 여전히
  미파싱으로 카운트해 진짜 형식 이상은 계속 잡아낸다). 수정 후 파싱률 100%(415/415).
- 메시지 중간의 빈 줄(문단 구분)은 원본 그대로면 사라진다 — 빈 줄을 전부 스킵하는
  기존 동작 때문에 멀티라인 메시지 내부의 의도된 빈 줄도 함께 없어진다. 내용 손실은
  아니고 서식만 약간 뭉개짐(성공 기준에는 영향 없음, 필요해지면 개선).

## parse_txt.py 처리 방침

1. 형식 A 정규식으로 먼저 매칭 시도
2. 실패하면 형식 B(날짜 헤더 + 대괄호 메시지) 정규식으로 시도
3. 둘 다 실패하고 시스템 메시지 키워드가 포함되어 있으면 `is_system=True`로 최선 추정 기록
4. 그마저도 실패하면, 직전 메시지가 있으면 그 메시지의 멀티라인 후속 줄로 보고 이어붙인다
5. 직전 메시지가 없으면(파일 맨 앞 등) 그제서야 미파싱 라인으로 카운트 (설계서 §2.4 A1 파싱률 기준에 반영)
