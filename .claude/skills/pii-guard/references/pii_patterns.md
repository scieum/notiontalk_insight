# PII 마스킹 정규식 목록 (pii_patterns.md)

> 설계서 §2.4 A6. mask.py가 사용하는 패턴과 그 근거. 새 패턴을 추가하면 이 문서도 갱신한다.

| 패턴 | 정규식(요약) | 대체 텍스트 | 비고 |
|------|-------------|-----------|------|
| 휴대폰 번호 | `01[0-9][- .]?\d{3,4}[- .]?\d{4}` | `[전화번호 마스킹]` | 010/011/016~019 등, 구분자(- . 공백) 유무 모두 허용 |
| 일반 전화번호(지역번호) | `0\d{1,2}[- .]?\d{3,4}[- .]?\d{4}` | `[전화번호 마스킹]` | 서울(02) 등 지역번호 포함. 휴대폰 패턴과 겹치지 않도록 먼저 휴대폰 패턴을 적용 |
| 이메일 | `[\w.+-]+@[\w-]+\.[\w.-]+` | `[이메일 마스킹]` | |
| 주민등록번호 | `\d{6}-?[1-8]\d{6}` | `[주민번호 마스킹]` | 성별 코드 1~8까지 허용(구/신 체계 모두 커버). 오탐 가능성보다 과탐이 안전하다는 원칙(항상 마스킹) |
| 노션 공유 링크 토큰 | `(https?://[\w.-]*notion\.so/\S+?)\?[^\s]*` | `\1` (쿼리스트링 제거) | 페이지 자체 링크는 유지하되 `?pvs=`, 공유 토큰 등 쿼리 파라미터만 제거 |

## 항상 적용 vs 모드 의존

- 위 표의 패턴은 `consent.yaml`의 `mode`와 무관하게 **항상** 적용한다.
- 닉네임 처리(가명 치환)는 `mode: anon`일 때만 적용한다 — 이건 이 문서가 아니라
  `anonymize.py`의 책임.
- 시스템 메시지의 입장/퇴장 문구(예: "OOO님이 들어왔습니다.")는 모드와 무관하게
  **항상** 제거한다 (`SYSTEM_EVENT_RE`, apply.py에서 처리).

## 재검사 실패 시 처리

A6 처리 후 마스킹된 결과에 대해 같은 패턴으로 다시 스캔한다(재귀적 마스킹 누락
방지). 재검사에서도 매치가 남아 있으면 해당 인사이트 항목은 최종 출력에서
제외하고 에스컬레이션한다 — 절반만 마스킹된 상태로 발행하지 않는다.
