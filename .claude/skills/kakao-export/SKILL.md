# kakao-export (A0')

> 상태: **미구현 (V1' 착수 중)**. 설계서 §2.4 A0'.
> O1''' 부분 해소 (2026-08-26, 카톡 26.7.0 정적 분석):
> **메뉴 라벨이 설계서 가정과 다르다** — "대화 내보내기"가 아니라
> **"텍스트 파일로 저장"**(채팅방 설정 → 대화 내용 관리 → 대화 내용 저장)이다.
> 이름이 비슷한 **"채팅방 저장소에 저장"은 톡클라우드 유료 업로드**라 절대 누르면
> 안 되고, 바로 옆에 **"대화 내용 삭제"**가 있어 좌표 클릭은 금지다.
> 상세·잔여 확인 항목은 [references/export_ui.md](references/export_ui.md) 참조.
> **잔여 관문**: 오픈채팅방에서 이 메뉴가 실제로 활성인지 실기기 확인.

## 목적

DB 직접 읽기가 불가능할 때 공식 "대화 내보내기"를 UI 자동화로 실행해
`/inbox/raw/<timestamp>.txt`를 생성한다.

## 처리 순서

1. `/inbox/raw/`에 미처리 파일 존재 여부 확인 → 있으면 내보내기 생략, 그 파일 사용
2. JXA 스크립트가 카카오톡 앱 활성화 → 대상 오픈채팅방 선택 →
   채팅방 설정 → 대화 내용 관리 → 대화 내용 저장 → **"텍스트 파일로 저장"** 클릭
   - 요소 매칭은 **한국어 라벨 문자열로만** 한다. 좌표 클릭 금지 (옆에 "대화 내용 삭제"가 있음)
   - `Export`/`저장소` 문자열로 매칭하면 톡클라우드 유료 경로를 누른다 — 금지
3. 파일 존재·크기·최신 메시지 시각 확인

## 스크립트

| 스크립트 | 역할 | 상태 |
|---------|------|------|
| `scripts/export.jxa` | 카톡 UI 자동화로 내보내기 실행 | 미구현 — 오픈채팅방 지원 확인·대상 방 이름 확보 후 착수 |
| `scripts/verify_export.py` | 파일 존재·크기·형식·최신 시각 검증 | **구현·테스트 완료 (2026-08-26 Mac)** |

## 입력/출력

- 입력: kakao-db-reader 실패 신호
- 출력: `/inbox/raw/<timestamp>.txt`

## 성공 기준 / 실패 처리

CLAUDE.md §5 표의 A0' 행 참조. 60초 간격 2회 재시도 → 실패 시 macOS 알림 +
`/output/escalations/` 기록. 3사이클 연속 폴백 시 "DB 경로 점검 또는 폴백 상시화"
결정을 운영자에게 에스컬레이션.

## verify_export.py 판정 (구현됨)

| 판정 | 의미 | 호출자 동작 | exit |
|------|------|------------|------|
| `ok` | 형식 인식 + 신규 메시지 있음 | A1로 진행 | 0 |
| `empty` | 메시지 0건 ("주고받은 대화 내용이 없습니다") | **재시도 금지**, skip+로그 | 0 |
| `stale` | 최신 메시지가 `--since`(last_ts) 이후가 아님 | 신규 구간 없음, skip+로그 | 0 |
| `suspect` | 형식 미인식 | 에스컬레이션(파서 갱신 필요) | 2 |
| `missing` | 파일 없음 | 호출자가 60초 간격 2회 재시도 | 2 |

`empty`/`stale`을 재시도로 처리하지 않는 게 핵심이다 — 둘 다 같은 결과가 반복되므로
CLAUDE.md §5의 "60초 간격 2회 재시도"는 `missing`에만 적용한다.

본문은 스캔만 하고 어디에도 보관하지 않는다 — 로그·JSON에는 건수·형식·시각만 남는다 (C2, R4).
운영자가 수동으로 `/inbox/raw/`에 넣은 파일(CLAUDE.md §8)도 같은 검증을 거친다.
