# 리포트 디자인 시스템 (design.md)

> 주간 리포트의 시각 언어를 정의한다. 무엇을 어떤 순서로 싣는지는
> [report_format.md](report_format.md)에, 실제 구현은
> [scripts/render_report.py](../scripts/render_report.py)의 `TEMPLATE`·`CSS`에 있다.

## 1. 기준

TalkInsight는 notiontalk.com 커뮤니티의 파생 콘텐츠다. 별도 제품처럼 보이는 테마를
만들지 않고 **notiontalk.com 뉴스레터의 발행 규격과 사이트의 색·서체·표면 문법을
그대로 계승**한다.

- 코드 기준 원본: `notiontalk-landing/app/globals.css`
- 화면 기준 원본: `notiontalk-landing/app/contents/community/page.tsx`
- 발행 규격 기준: `newsletter-self-host/app/letters/[slug]/page.tsx`
- 이메일 규격 기준: `newsletter-self-host/lib/email-templates.ts`
- 리포트는 외부 CSS를 불러오지 않는 독립형 HTML이므로 원본 토큰을 CSS 변수로
  복사해 인라인한다.
- 원본 토큰이 바뀌면 이 문서와 `render_report.py`를 함께 갱신한다.

## 2. 브랜드 토큰

| 원본 토큰 | 값 | 리포트 용도 |
|---|---:|---|
| `--color-paper` | `#F4F4F4` | 이메일 바깥·코드·보조 면 |
| `--color-paper-dark` | `#ECECEC` | 코드·보조 면 |
| `--color-dark` | `#1C1917` | 제목·본문 |
| `--color-dark-light` | `#292524` | 강한 보조 글자 |
| `--color-accent` | `#1F5D5C` | 링크·상태·주요 CTA |
| `--color-accent-hover` | `#154645` | hover |
| `--color-sub` | `#57534E` | 보조 본문 |
| `--color-muted` | `#A8A29E` | 라벨·메타 |
| `--color-edge` | `#E7E5E4` | 경계선 |

리포트에서만 필요한 파생색은 원본 토큰에서 계산하거나 최소한으로 추가한다.
현재 `--color-accent-soft`는 팁·카운트의 옅은 녹색 면에만 쓴다. 원본 muted는 작은
글자에 대비가 부족하므로, 필수 메타 텍스트에는 접근성 파생 토큰
`--color-meta: #746F6A`를 쓴다.

## 3. 타이포그래피

Pretendard Variable 하나만 사용한다. 독립 HTML에서는 사용 글자만 서브셋해 data URI로
넣고, 서체가 없을 때는 시스템 한글 산세리프로 폴백한다.

| 역할 | 크기·굵기 | 세부 규칙 |
|---|---|---|
| 리포트 제목 | `clamp(1.9rem, 3vw, 2.25rem)` · 600 | 뉴스레터 상세와 동일, 자간 `-.04em`, 행간 1.14 |
| 섹션 제목 | `clamp(1.35rem, 2.8vw, 1.75rem)` · 600 | 자간 `-.03em` |
| 카드 제목 | 1rem · 500 | 자간 `-.02em` |
| 본문 | 1rem · 400 | 행간 1.7 |
| 도입 | 1.0625rem · 300 | 자간 `-.02em`, 행간 1.75 |
| 영문 라벨 | .6875rem · 600 | 대문자, 자간 `.18em` |
| 메타 | .75rem | muted, 숫자는 tabular |

한글은 `word-break: keep-all`, 긴 URL은 `overflow-wrap: anywhere`로 처리한다.

## 4. 페이지 구조

### 사이트 크롬

- notiontalk.com과 같은 56px 고정 바를 둔다.
- 왼쪽은 `노션톡 / Community Insight`, 오른쪽은 `커뮤니티 / 홈페이지`다.
- 실제 사이트에 통합할 때는 이 축약 바를 본체 `SiteNav`로 대체할 수 있다.

### 호별 머리말

- 바깥 프레임은 72rem(`max-w-6xl`)이지만 실제 발행 본문은 뉴스레터 상세와 같은
  왼쪽 42rem(`max-w-2xl`) 단일 열을 쓴다. 오른쪽 여백을 콘텐츠로 채우지 않는다.
- `Notion Talk · Community Insight` → 제목 → 도입 → 방 이름·호수·기간 순서는
  뉴스레터의 시리즈 라벨 → 제목 → 부제 → 작성자·날짜 문법을 계승한다.
- 기간은 `2026.08.19 - 08.26`처럼 하이픈으로 표시한다.
- 통계는 떠 있는 요약 카드가 아니라 제목 아래의 얇은 가로 메타 스트립이다.
- 모바일에서만 통계를 2열 카드형으로 접어 가독성을 확보한다.
- 초안·자동생성·운영자 검토 전 문구는 안전 장치이므로 항상 유지한다.

### 목차

긴 회보를 빠르게 훑도록 여섯 고정 섹션의 가로 목차를 둔다. 사이트 바 아래에 sticky로
남고, 모바일에서는 가로 스크롤한다. `prefers-reduced-motion`에서는 부드러운 스크롤을
끄고 즉시 이동한다.

### 본문

- 웹·모바일 모두 뉴스레터와 같은 한 열 읽기 흐름이다.
- 섹션 뼈대와 순서는 매 호 고정한다. 0건도 숨기지 않는다.
- FAQ·팁을 임의 개수로 자르지 않고 `final.json`의 전체 항목을 렌더한다.

### 이메일 검토본

- `--email-preview`는 같은 전체 데이터를 640px 한 열 HTML로 만든다.
- 웹의 sticky 목차·hover·인쇄 규칙은 이메일에 복제하지 않는다.
- 메시지·해결된 질문·실무 팁 세 통계를 헤더 아래에 보여주고 본문 항목은 축약하지 않는다.
- 산출물에는 검토용이며 자동 발송되지 않는다는 표시가 항상 있어야 한다.

## 5. 컴포넌트 문법

- **주요 주제**: 카드 대신 번호·얇은 구분선으로 읽기 흐름을 만든다.
- **해결된 질문**: 답변 단위만 흰 surface 카드로 묶는다. 실제로 채택된 답과 실무 팁을
  한 덩어리로 읽어야 하므로 카드가 정보 계층을 설명한다.
- **미해결·액션**: 흰색의 얇고 짧은 행. 빈 원·사각형 마커가 의미를 구분한다.
- **팁**: 기능 태그 아래 한 열 카드로 쌓아 뉴스레터의 읽기 폭을 지킨다.
- **함께하기**: 페이지에서 유일한 채움 accent 면. 버튼과 함께 실제 오픈채팅 URL을
  평문 링크로 항상 보여준다.
- **판권**: 큰 카드로 감싸지 않고 상단 경계선과 작은 메타 그리드로 끝낸다.

## 6. 접근성·반응형·인쇄

- 문서에 doctype, `lang="ko"`, charset, viewport, `<main>`을 둔다.
- 첫 포커스 요소는 `본문으로 건너뛰기` 링크다.
- 모든 링크와 버튼에 `:focus-visible` 윤곽선을 둔다.
- print에서는 사이트 바·목차·버튼을 숨기고, 배경과 그림자를 제거한다.

## 7. 공개 통합 경계

이 렌더러가 만드는 파일은 언제나 **검토 전 초안**이다. 그대로 공개 경로에 노출하지
않는다. 공개본은 G-R 검토와 발행 상태를 통과한 별도 산출물이어야 한다.

notiontalk.com 연결 원칙:

- 새 최상위 메뉴를 더하기보다 커뮤니티 랜딩의 첫 섹션과 이벤트 갤러리 사이에
  최신 인사이트와 이전 호 진입 영역을 둔다.
- 공개 정본 URL과 newsletter-self-host 인계 방식은 후속 통합 PR에서 하나로 확정한다.
- 이 저장소 PR은 검토 렌더까지이며, 공개 라우트·사이트맵·공유 내비게이션·SES 발송을
  수행하지 않는다.
