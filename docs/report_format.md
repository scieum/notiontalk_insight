# 리포트 형식 (report_format.md)

> A4(인사이트 추출)의 리포트 생성 프롬프트와 A7(노션 발행)의 블록 배치가 따르는 형식
> 정의. 운영자가 2026-08-26에 [huddling.ai AI Report](https://huddling.ai/ai-report/1)
> 1·2호를 레퍼런스로 지정해 확정했다.
>
> **설계서 §3.2 스키마와의 관계**: §3.2의 `report.sections`(topics/resolved/
> unresolved/decisions/stats)는 그대로 유지한다 — 그것이 *사실 데이터*이고,
> 이 문서는 그 데이터를 어떤 *표현*으로 배치할지를 정한다. 다만 huddling 톤의
> 핵심인 후킹 제목·도입문·항목별 실무 팁은 LLM이 생성해야 하므로 §3.2에
> 필드 3개를 추가한다(아래 "스키마 추가분").

---

## 1. 레퍼런스에서 가져오는 것 / 버리는 것

huddling 리포트는 **라이브 이벤트 + 인터뷰 + 외부 뉴스 큐레이션**으로 구성된
뉴스레터다. TalkInsight의 원천은 **오픈채팅방 대화 로그 하나뿐**이라 절반의
섹션은 원천 자체가 없다.

| huddling 섹션 | TalkInsight 처리 |
|---|---|
| 후킹형 제목 + 짧은 도입 | **채택** — LLM 생성 |
| Cycle/Speaker Live (영상 하이라이트) | **제외** — 원천 없음 |
| Huddling LAB (자체 실험·통계) | **제외** |
| Winner/First Penguin Interview (Q&A 원문) | **제외** — 사람이 수행하는 취재 |
| AI News (요약 + 실무 팁 + 원본 링크) | **제외** — 외부 큐레이션 |
| Get Involved (CTA) | **채택** — 고정 텍스트 |

운영자 결정(2026-08-26): 위 표에서 **제외**로 표시한 섹션(인터뷰·라이브·외부 뉴스)은
리포트에 아예 두지 않는다. 매 호 사람 손이 들어가야 하는 구조를 만들지 않는다는
뜻이다. 이것은 "원천이 없는 섹션은 만들지 않는다"는 뜻이고, **채택한 섹션이 그 주에
0건인 것과는 다른 이야기다** — 후자는 §2대로 섹션을 유지하고 0건임을 적는다.

**채택하는 것은 형식과 톤이지 섹션 목록이 아니다.** 구체적으로:

- 제목은 라벨이 아니라 **질문형 후킹** ("내 클로드 코드는 왜 점점 멍청해질까?")
- 문단보다 **스캔 가능한 리스트** 우선
- 각 항목 끝에 **실무 팁 한 줄** (huddling AI News의 핵심 장치)
- 경어체, 이모지 없음, "우리가/함께" 같은 포용적 어휘
- 전체 2,500~3,000자 규모

## 2. TalkInsight 리포트 구조 (고정)

**뼈대는 매 호 완전히 고정이다** (2026-08-26 운영자 결정, huddling 2호 기준).
섹션 목록·순서·영문 라벨·한글 제목·설명문이 매주 같다. 항목이 0건이어도 섹션을
없애지 않고 "이번 주에는 없었습니다"를 적는다 — 독자가 매주 같은 자리에서 같은
것을 찾을 수 있어야 하고, 0건이라는 사실 자체가 정보이기 때문이다.

각 섹션은 `영문 라벨 → 한글 제목 → 고정 설명문 → 내용` 순서로 연다.

| 순서 | 영문 라벨 | 한글 제목 |
|------|-----------|-----------|
| 1 | This Week | 이번 주 주요 주제 |
| 2 | Solved | 해결된 질문 |
| 3 | Open | 아직 답이 없는 질문 |
| 4 | Tips | 이번 주의 팁 |
| 5 | Actions | 하기로 한 것 |
| 6 | Get Involved | 함께하기 |

구현은 [scripts/render_report.py](../scripts/render_report.py)의 `SECTIONS` 상수 하나에
모여 있다. 섹션을 바꾸려면 그 상수와 이 표를 같이 고친다.

### ① 제목 + 도입 — `hook_title`, `intro`

- `hook_title`: 이번 주에 가장 많이 다뤄졌거나 가장 막혔던 주제를 **질문형**으로.
  40자 이내. 방 이름·기간을 제목에 넣지 않는다(그건 노션 속성으로 들어간다).
- `intro`: 2~3문장, 120자 내외. 이번 주가 어떤 한 주였는지 한 문단. '구간'이라는 말은 쓰지 않는다.

### ② 이번 주 주요 주제 — `sections.topics`

- 상위 3~5개. 각 항목: 주제 한 줄 + 왜 화제였는지 한 줄.
- 선정 근거는 메시지 수·참여자 수·미해결 여부(설계서 §2.3-5).

### ③ 해결된 질문 — `sections.resolved` (= `faq` 항목과 연결)

- Q&A 형식. 질문은 원문 뉘앙스를 살리되 다듬고, 답변은 **방에서 실제로 채택된 해답**.
- 각 항목 끝 `practical_tip` 한 줄.

### ④ 아직 답이 없는 질문 — `sections.unresolved`

- 답변이 안 달렸거나 결론이 안 난 질문. 이 섹션이 다음 주 참여를 유도한다.
- 팁을 붙이지 않는다(답을 모르는 상태이므로).

### ⑤ 이번 주의 팁 — `tips`

- 누군가 공유한 노하우. `feature_tags`는 `notion_feature_taxonomy.md`에서 선택.
- 각 항목 끝 `practical_tip` 한 줄.

### ⑥ 결정·액션 — `sections.decisions` (= `actions`)

- 방에서 합의된 것, 누가 뭘 하기로 한 것. 0건이면 섹션을 없애지 않고 "이번 주에는 정해진 약속이 없었습니다"를 적는다(§2 고정 뼈대).

### ⑦ 이번 주 숫자 — `sections.stats`

- 메시지 수, 함께한 선생님 수, 스레드 수, 질문 수/그중 해결된 수.
- 문장이 아니라 숫자 나열로.

### ⑧ 함께하기 — 고정 CTA

- 대화에서 생성하지 않는 유일한 섹션.
- **매 호 한 글자도 달라지지 않는다**(2026-08-27 운영자 지정). 그 주 숫자나
  미해결 개수 같은 가변 값을 넣지 않는다. 매번 같은 자리에서 같은 말이 나와야
  참여 안내로 작동한다.
- 구성: `GET INVOLVED` 라벨 / "선생님, 같이 노션 배워볼래요?" /
  "혼자 헤매면 오래 걸리는 일도 함께하면 금방 풀립니다." / 버튼 2개.
- 버튼: 오픈채팅방 참여(채움), 노션톡 홈페이지(테두리). 링크는
  `render_report.py`의 `OPENCHAT_URL` · `HOMEPAGE_URL` 상수에 있다.

## 2'. 시각 규칙

시각 언어는 [design.md](design.md)에 따로 정리했다 — 팔레트 토큰, 타이포 스케일,
카드·마커 규칙, 테마 3상태 처리. 요약하면:

- **기조는 huddling.ai AI Report**: 거의 검정에 가까운 차가운 회보라 바탕 + 파랑 액센트 하나.
- **글꼴은 Pretendard 하나.** 위계는 서체 교체가 아니라 가변 굵기축으로 만든다.
- **다크가 기본**이고 밝은 테마도 지원한다(시스템 설정 / 명시적 라이트 / 명시적 다크).
- 호수(`N호`)를 머리말에 표시한다.

## 3. 스키마 추가분 (설계서 §3.2 확장)

```json
{
  "report": {
    "hook_title": "",          // 추가: 질문형 후킹 제목 40자 이내
    "intro": "",               // 추가: 도입 2~3문장
    "title": "",               // 기존 유지: 사무적 제목(노션 페이지 제목용)
    "sections": { "topics": [], "resolved": [], "unresolved": [], "decisions": [], "stats": {} },
    "source_thread_ids": []
  },
  "faq":  [ { "...": "", "practical_tip": null } ],   // 추가
  "tips": [ { "...": "", "practical_tip": null } ]    // 추가
}
```

`practical_tip`은 **선택 필드**다 — 팁이 억지스러우면 `null`을 넣는다. 없는 팁을
지어내는 것이 빈 자리보다 나쁘다(A5 충실성 축에서 걸린다).

## 4. 톤 규칙 (A4 프롬프트에 그대로 주입)

1. 경어체(`~합니다`). 이모지 금지.
2. 한 문장 60자 이내. 두 가지를 말하려면 문장을 나눈다.
3. 대화 원문을 그대로 길게 인용하지 않는다 — 요약하되 왜곡하지 않는다.
4. 방 참여자를 평가하거나 훈계하지 않는다.
5. 단정할 근거가 없으면 "~로 보입니다"가 아니라 **미해결 섹션으로 보낸다**.
6. 닉네임 표기는 `consent.yaml` 모드를 따른다 — A4는 닉네임을 그대로 쓰고,
   익명화는 A6가 한다(A4가 미리 익명화하면 A5가 근거 대조를 못 한다).
7. 익명 모드의 가명은 **"함께한 선생님A"** 형식이다(2026-08-26 운영자 지정).
   접두어는 `pii-guard/scripts/anonymize.py`의 `PSEUDONYM_PREFIX` 한 곳에 있다.
8. 대화가 오간 곳은 **"오픈채팅방"**이라고 쓴다. "방"이라고 줄이지 않는다
   (2026-08-26 운영자 지정). 단 "방법·방식·방안" 같은 낱말은 당연히 그대로 둔다 —
   일괄 치환하면 "오픈채팅방법"이 된다.

## 5. 이 문서를 고칠 때

리포트 형식이 바뀌면 (1) 이 문서, (2) A4 프롬프트, (3) A7 블록 배치 세 곳이 같이
바뀌어야 한다. G-R 반려 사유가 형식 문제로 반복되면 여기부터 고친다.
