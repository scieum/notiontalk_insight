## 승인 대상 (중요)

승인한 것은 **직접 복호화가 아니라 `katok` CLI 위임 경로**다. 이 차이가 리스크
평가를 바꾼다 — 상세는 [db_access_reference.md](db_access_reference.md)의
"katok CLI 경로" 절.

| 리스크 | 승인 시점 평가 |
|--------|---------------|
| R1 약관 | **그대로 남는다.** 도구가 대신 읽을 뿐 비공식 로컬 DB 접근이다. katok의 DISCLAIMER도 "카카오가 개발·승인·보증한 제품이 아니다"라고 명시한다. **이 승인은 이 리스크를 감수하겠다는 뜻이다** |
| R2 취약성 | 완화 — 앱 업데이트 대응은 업스트림이 한다 |
| R3 참조 구현 신뢰성 | 크게 완화 — 복호화 코드를 직접 쓰지 않는다 |
| R4 키 자료 | 크게 완화 — katok이 `{user_id, uuid}`만 mode 0600 캐시로 두고 키 material 자체는 저장하지 않는다 |
| R5 개인정보 노출 면적 | 완화 — `transcript --chat <id>`로 대상 방만 뽑는다. 다만 katok 아카이브 자체에는 전 채팅방이 들어간다 |

추가로 katok DISCLAIMER §2는 "제3자 데이터 처리" 용도라면 전문가 자문과 카카오
승인을 권고한다. 이 시스템은 오픈채팅방 참여자들의 대화를 요약해 발행하므로 그
범주에 가깝다. 운영자는 이를 안내받은 상태에서 승인했다.

## 승인 범위 밖

- `katok send`(메시지 발신)는 포함되지 않는다. 제약 C1이 금지하며,
  `katok_extract.py`가 명령 화이트리스트로 실행 자체를 막는다.
- 대상 방(`room_profile.md`의 방 이름) 외 다른 채팅방의 내용을 우리 산출물에
  남기는 것은 포함되지 않는다(R5).
